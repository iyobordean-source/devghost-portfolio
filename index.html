01 / About

A developer who'd rather ship something useful than perfect something invisible.

I got into software development around 2024, starting with the basics of web development the usual path of tutorials, small experiments, and a lot of trial and error.

Since then I've spent most of my time learning by building: real websites, small web applications, business landing pages, and side projects that started as "what if I built this for myself or a friend." Some were built for people running actual businesses, others were built purely to solve a problem I was personally dealing with.

I'm mainly interested in full-stack development and software engineering more broadly. Right now I'm expanding beyond the frontend into backend development, automation, and the parts of engineering that don't show up on a landing page but make software actually work.

What keeps me building is the same thing every time: taking an idea or a problem and turning it into something that functions — something a real person can actually use.

05 / My Approach

I don't just build websites. I build around problems.

  1. 01

    Understand the problem

    Before touching code, I figure out what's actually broken or missing — for the user, the business, or myself.

  2. 02

    Plan the solution

    I map out what needs to exist: the core features, the structure, and what technology actually fits the problem.

  3. 03

    Build the product

    I build in working increments, keeping things functional at every stage instead of one long build toward the end.

  4. 04

    Test and refine

    I check it against real use — devices, edge cases, and whether it actually solves what it was meant to solve.

  5. 05

    Deploy and improve

    Shipping isn't the finish line. I keep iterating based on what I learn once something is actually in use.
